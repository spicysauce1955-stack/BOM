# Contract v1.2 — impact audit against the implementation

**Date:** 2026-08-30 · **Contract:** v1.2 (`947dc8fd…`, ratified) · **Method:** every
finding measured against the first real published snapshot
(`3ae88642…json`, 75 source docs, 4 parameter tables, 81 gaps, 289 warnings),
not against our own fixture. Adversarially reviewed by two independent agents
(edge-cases/invariants; boundary-validation/data-integrity).

**The one-line result:** the `Date` work v1.2 obliges is real but small. The audit's
material finding is that **identity and invariant-checking are systematically
under-built on the ingest path** — and that two things in v1.2 itself cannot be
implemented as written.

## 1 · Confirmed findings, ours to fix

Ordered by blast radius, not by contract section.

**C1 · `object_id` and gap ids omit the table's scope — BLOCKER.**
`parameters.py:275` builds `object_id=f"{parameter}#{index}"`; `:342` builds
`gap:uncovered:{parameter}:{where}`. The real snapshot publishes `footing_depth_mm`
and `footing_diameter_mm` **twice each**, distinguished only by `scope.id` (Barrette
vs CertainTeed) — and the two cite different authorities, one `superseded_by` the
other. Result: 16 rows → 8 refs. This corrupts (a) the decision graph, which cites
`footing_depth_mm#0@v1` and cannot say which manufacturer's approval it used, (b)
`snapshot_set()`/`snapshot_hash()`, whose knowledge identity stops being injective,
(c) `overrides_objects`, which would defeat both rows at once, and (d) the curator's
queue, where the CertainTeed holes vanish behind the Barrette ones. All 16 values
happen to agree today, which is exactly why nothing failed.

**C2 · The `Date` type does not exist — v1.2 BINDING.**
`valid_from`/`valid_until` are `str | None` (`parameters.py:112-113`); a conforming
`{"iso": …, "value_raw": […]}` is rejected outright. `SourceDoc` is not modelled at
all, so `issue_date` can never reach §1.4.

**C3 · Ordering a date we cannot read, and never reading the other one.**
The lapsed guard (`parameters.py:298`) is a *shape* regex, not a date check:
`valid_until="2025-13-45"` is compared and reported lapsed. And `valid_from` is
**never read anywhere in `src/`** — a row that is not yet in force expands silently
with no marker. That is the asymmetric twin of the lapsed check and it fails in the
dangerous direction: lapsed produces a warned line, not-yet-in-force produces a
confident wrong answer.

**C4 · `source_docs` is `list[Any]` and reported as "unconsumed".**
It is not an unimplemented feature — it is the only carrier of `version_status`,
`source_class`, `issue_date` and `superseded_by`, i.e. every field a
`source_policy.Candidate` needs, and the resolution target of §1.2.1's closure rule.
The closure rule **holds** in real data (543 refs, 0 dangling); we simply never
check it, and could not.

**C5 · No `contract_version` gate — violates our own §3.2 obligation 3.**
*"Refuse a snapshot built against an unknown major — loudly, at load, not silently at
generate."* We accept `contract_version: "9.9.9"` without a word. The real snapshot
declares `1.1.0` and nothing notices, which is how C2 turns from a clean parse error
into a wrong lapse warning.

**C6 · `GapSubject` cannot represent v1.2's `ParamRef`.**
`{kind, id, tenant}` flattens `{parameter, scope: EntityRef, point}` into one opaque
string — which is precisely the shape we asked the publisher to *stop* sending.
`Because.params` cannot hold the point dict, and widening it naively hits a
coercion trap: pydantic lax mode turns `True` into `1`, so `hvhz` renders as `1`.

**C7 · We emit a slot-shaped `Gap.subject`, which v1.2 forbids.**
`generator.py:3249`: `GapSubject(kind="slot", id="post_ground")`. §1.1 marks
`SlotRef` RESERVED — *"No producer may emit a slot-shaped `Gap.subject`."* See §3:
the contract's stated evidence for that reservation is false about this repo.

**C8 · `resolve()`'s last tie-break is not a total order.**
`min(tied, key=source_class)` returns the *input-list-first* element when classes
tie. The real snapshot's two competing footing authorities are **both
`sealed_approval`, both `curation_level: 2`, both rank 1** — so the winner depends on
list order, and one ordering silently prefers the superseded document, which §1.4's
BINDING clause names as the thing it exists to prevent.

**C9 · Published and derived uncovered gaps double-count.**
The snapshot publishes all 16 `condition_point_uncovered` gaps; `expand()` derives
the same 16 from `table.uncovered`. 32 gaps for 16 holes.

**C10 · Our validator manufactures 276 false defects.**
`warnings.py:198` rejects any `document`/`warranty`/`maintenance` warning carrying a
`ref`. The publisher sets `ref` to *the document's own content_hash* — naming which
document, not naming a line. Contract §3.3.5 constrains only **where** such a warning
renders. The rule is ours, lives in a docstring we wrote, and passes today only
against the fixture **we authored** — the identical failure mode `plan/current-status.md`
already names for the ISO lapse check, one module over. No data is lost (annexe
grouping is unaffected), but we are currently prepared to tell the other team that
276 of their 289 warnings are malformed, and they are not.

**C11 · A publisher's mistake fails the entire ingest.**
`Gap.model_post_init` raises on a bad `closes_by`. That invariant is right for our
*emit* path and wrong for *ingest*: one malformed published gap loses 4 valid tables
and 289 warnings.

**C12 · `TenantId = str | null` is unrepresentable.**
`Snapshot.tenant` and `GapSubject.tenant` are `str`; a Knowledge-global snapshot
(`tenant: null`) is rejected. `ParameterTable.scope` already handles null correctly —
the two spellings are inconsistent inside one module.

**C13 · `hit_policy` is parsed and ignored.** Three of its four values silently
produce a wrong number (`collect_min` resolves to the first firing rule, not the
min). All four real tables are `unique`, so it is latent.

**C14 · The §1.3 `unique` BINDING is never checked**, and `is_fallback()` is dead
code guarding a check that does not exist. `hit_policy` was added to buy exactly this
mechanical property.

**C15 · `snapshot_id_for()` verifies nothing** while its docstring calls it "the one
property of a snapshot this side can verify without trusting the sender." It hashes
`parameters` alone and returns `0bd95701…` against a declared `3ae88642…`.

**C16 · `_display`'s `%g` misstates large values** (`1234567 → "1234.57 mm"`) and
discards `value_raw`, the lexeme §1.1 says exists to be shown.

**C17 · Two docstrings became false on 2026-08-30** — `source_policy.py`'s "no `Date`
type exists… neither side has agreed one", and `to_mm`'s "half-up" (it is
half-away-from-zero; the arithmetic is right, the word is wrong).

**C18 · Report-only, not a fix.** The real rows compile to
`bay.fence_height == '49" to 76"'`. Nothing in this engine binds `bay.fence_height`,
and the bracket's numeric bounds exist only inside the label string. Reading them out
would manufacture a fact. This is a missing concept at the boundary — a bracket is a
`Quantity` range, not a token — and item 6's wiring will otherwise land 16 rules that
resolve to nothing.

## 2 · Refuted or narrowed — recorded so they are not re-raised

- **The §1.2.1 closure rule is NOT violated.** 543 refs, 75 distinct hashes, 0
  dangling; `superseded_by` targets and row authorities all resolve. Unchecked, not
  broken.
- **`_display`'s float does not leak.** It is confined to a title that is never
  hashed and never read by a decision. The bug is `%g`, not the float.
- **`to_mm`'s negative rounding is correct.** Symmetric magnitude, never floors. Only
  the docstring is wrong.
- **C10 loses no data.** All 274 document warnings carry `cites` and none spans two
  documents, so annexe grouping produces 274 entries either way. It is a noise flood,
  not a correctness bug.

## 3 · Two defects in v1.2 itself — to file, not to code around

**X1 · §1.4's tie-break is intransitive, and incomplete. (Trigger B, unimplementable.)**
Three candidates tied on rank and curation, applying the ratified wording pairwise:

| | `source_class` | `issue_date` |
|---|---|---|
| A | `industry_standard` | `iso: null` |
| B | `sealed_approval` | 2024-01-01 |
| C | `company_authored` | 2020-01-01 |

A beats B (no shared date → lexicographic), B beats C (both dated → later wins),
C beats A (no shared date → lexicographic). **A 3-cycle**, verified by execution.

The general form: *"where both carry one"* is a **pairwise** predicate, and a pairwise
predicate that is not a total preorder cannot be a sort key. Any key-based
implementation must place a `null` date somewhere, and every position is either
earliest or latest — both forbidden by §1.1's own BINDING null rule. With 72 of 75
documents undated, mixed sets are the default path, not a corner.

It is also **incomplete**: when all four criteria tie, the chain ends with no answer.
The real snapshot contains exactly that pair.

**X2 · §1.1's stated evidence for `SlotRef: RESERVED` is false about this repo.**
The ratified parenthetical reads *"zero of 81 published gaps and zero Planning-emitted
gaps are slot-shaped."* The first half is true. The second is not:
`generator.py:3249` has emitted one since before ratification. We wrote that
parenthetical; the survey behind it was never run against our own emit path. Bringing
the code into conformance makes the sentence true going forward, but the reservation
rested on an unchecked claim and a worked example does exist — which is material to
anyone who later defines `SlotRef`.

## 4 · What this means for item 6

Item 6's `expand()` wiring stays blocked on more than the re-cut. **C1, C2 and C8
must land first** — wiring a policy on top of colliding `object_id`s and an
order-dependent winner would record `admitted_by` against an identity that cannot say
which manufacturer's approval it used. C18 additionally means the wired rules will
resolve to nothing until a bracket concept exists.
