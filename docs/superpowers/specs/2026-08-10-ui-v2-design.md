# UI v2 design — "editable, visible, Hebrew"

Approved by user 2026-08-10 (brainstorm session). Research basis: fence/CAD editor
grammar (ArcSite, Leaflet-Geoman, SVG-edit), civil plan-and-profile pattern, tldraw/
Figma undo reconciliation, W3C/Firefox RTL guidelines. Approach chosen: evolve the
vanilla SVG app (ADR-0010 holds); no framework, no canvas library.

Decisions from brainstorm:
- Hebrew-first UI with עב/EN toggle; full depth (explanations, warnings, AI
  interpretation, knowledge display — all localizable).
- Plan + synchronized unrolled side-view (profile) panel.
- Full editing grammar: move/delete/insert dots, undo/redo, typed exact lengths,
  snapping & guides.
- Desktop-first, touch-friendly (≥44 px effective hit targets, tap = click).

## 1. Canvas & editing grammar

Left icon toolbar; exactly one active tool; a status bar always names the current
mode and next gesture (no secret gestures — root cause of the "clear doesn't work"
report was the invisible draft layer + undiscoverable double-click-to-finish).

Tools: **Select** (default), **Draw**, **Gate**, **Base**, **Ground point**,
**Pin post**, plus Undo/Redo/Clear buttons.

- **Select**: click run → vertex handles (squares) + midpoint ghosts (circles).
  Drag handle = move dot (snapped; events/gates re-anchor proportionally via the
  existing anchor model). Drag ghost = insert corner. Click dot + Delete key or ✕
  = remove dot (removing an end node of a 2-node run deletes the run, with confirm).
  Click a run's length label → inline mm input; Enter stretches the run to the exact
  length — the run's END node (draw-order) translates along the last segment
  direction; the label tooltip states this.
- **Draw**: click places dots (snapped) with live rubber-band length readout;
  Enter or double-click finishes; Esc cancels; visible Finish/Cancel buttons while
  a draft exists. Consecutive dots share nodes with existing dots within 100 mm
  (unchanged).
- **Gate/Base/Ground point/Pin post tools**: click the tool, then click a position
  on a run → popover with the values (gate: width + kit sku; base: surface + start/end
  stations prefilled from the click, editable; ground point: z; pin: none) → saves. The old side-panel forms are
  replaced by these popovers; the inspector still lists and deletes events.
- **Snapping**: 100 mm grid, existing dots, and 0°/45°/90° angle guides while
  drawing/dragging, with visual snapped-state feedback; Alt disables temporarily.
- **Clear topology**: clears draft layer too; confirm dialog; undoable.

## 2. Undo/redo

`history.js`: stack of deep-copied `{topology, overrides}` snapshots pushed once per
committed gesture (drag-end, draft finished, event/override added or removed, delete,
clear, typed-length apply). Not pushed for non-user changes (server responses,
project switch — tldraw's 'user'-source principle). Ctrl+Z / Ctrl+Shift+Z (⌘ on Mac)
+ toolbar ↶ ↷ with enabled/disabled state. Undo/redo restores the snapshot locally
and PUTs it as a NEW forward revision — server revisions are monotonic, never rolled
back. Redo stack clears on any new gesture. Cap 100 entries. Undo stack resets on
project switch.

## 3. Side-view profile panel

`profile.js`, rendered in a panel under the plan canvas (collapsible; remembers
state). Shows the **selected run** (Select tool's selection; defaults to first run).

- Axes: horizontal = station mm (ticks + cumulative labels at dots/posts); vertical
  = elevation with 1×/5× exaggeration toggle. Not mirrored in RTL.
- Rendered layers: ground line (elevation samples), wall-top line (wall_profile
  events), dashed height-intent line, and — when a generation result exists —
  panels (stepped = staircase rectangles, raked = parallelograms, level = flat),
  posts (vertical lines to ground), gate openings.
- Editing: drag a ground sample vertically (snapped to 10 mm) or click it to type
  z; double-click the ground line to add a sample at that station; drag wall-top
  endpoints vertically. Height intent remains form/popover-set but always visible.
  All profile edits are gestures → undo stack + PUT.
- Sync: hover/click a post/panel/dot in either view highlights it in both and (for
  generated elements) opens the inspector/decision trail.

## 4. Hebrew & RTL

- Default locale `he`, toggle עב/EN in header, persisted in localStorage; sets
  `<html dir lang>`. UI chrome mirrors via CSS **logical properties** (audit and
  replace physical left/right); the plan canvas and profile station axis are NEVER
  mirrored (maps depict physical reality). Undo/redo arrow semantics not flipped.
- `i18n.js`: `t(key, params)` over JSON tables `web/static/i18n/{he,en}.json`;
  static HTML uses `data-i18n` (and `data-i18n-placeholder/title`) walked on locale
  change; all dynamic strings go through `t()`. No i18n framework.
- Font: Noto Sans Hebrew (SIL OFL) bundled locally in `web/static/fonts/` with a
  Latin fallback stack; no CDN (self-contained app).
- Bidi hygiene: SKUs/ids/dimension strings wrapped in `<bdi>` or `dir="ltr"` spans;
  numeric inputs `dir="ltr"`; Hebrew uses European digits; dimension order
  ("2400 × 1800") never reorders.
- Server-side language:
  - `decisions/explain.py`: template tables per language; `GET
    /api/runs/{id}/explain/{el}?lang=he|en` (default en). Knowledge refs and SKUs
    stay verbatim inside localized sentences.
  - `StrategyWarning` gains `params: dict`; generator/critic messages become
    `code + params` (English `message` retained as fallback); the client localizes
    by code. Critique notes get a `code` too.
  - Stub interpreter: capped Hebrew keyword additions (גובה, שער, פרטיות, ליישר עם,
    עמוד, גדר …) mirroring the existing English demo set — S14 works offline in
    Hebrew. The Claude adapter needs only a system-prompt note that annotations may
    be Hebrew; source_text stays verbatim Hebrew.
  - Display names: `Product.name_i18n: dict[str, str]` and `KnowledgeVersion.
    title_i18n: dict[str, str]` (optional; fallback to `name`/`title`). Demo catalog
    + demo KB get Hebrew names. User-authored content keeps whatever language it was
    written in (already unicode-safe).

## 5. Layout & look

- Header: project selector · new-project · עב/EN toggle · AI badge.
- Left vertical icon toolbar (top-aligned tools, bottom-aligned ↶ ↷ 🗑). In RTL the
  toolbar moves to the right edge (chrome follows reading direction).
- Center column: plan canvas; profile panel below (drag-resizable height,
  collapsible).
- Inspector panel on the reading-direction end: selected dot (typed x/y), run
  (length, events list with delete), generated element (decision trail via
  `/explain?lang=`, correction box), overrides list.
- Status bar: mode + gesture hint + live cursor "station / x,y" readout.
- Existing tabs (Annotations, Knowledge, Review, BOM, Inventory) remain, translated
  and RTL-mirrored; their inline event forms are removed in favor of canvas tools
  (annotation composer stays).

## 6. Backend changes (contained; no domain-logic change)

Files: `decisions/explain.py` (lang tables), `strategy/model.py` (+`params` on
StrategyWarning), `generator.py`/`ai/stub.py` (codes+params, Hebrew keywords),
`catalog/model.py` + `knowledge/model.py` (+`name_i18n`/`title_i18n` optional),
`catalog/demo.py`/`knowledge/demo.py` (Hebrew names), `api/app.py` (lang query
param). All additive; existing tests remain green.

## 7. Testing & verification

- Python: Hebrew + English explanation snapshot tests; S14-Hebrew scenario (stub
  interprets Hebrew annotation offline); warning code/params tests; i18n-name
  fallback tests.
- UI: `tools/ui_smoke.py` — CDP script that seeds a project, draws by synthetic
  clicks, drags a dot, inserts a corner, types an exact length, undoes/redoes,
  places a gate, edits ground in the profile, switches to Hebrew, and screenshots
  LTR + RTL. Run at milestones; documented in the runbook; not part of pytest.
- Regression: draft/clear interaction (the reported bug) is an explicit smoke step.

## Out of scope (deliberate)

3D/isometric view, mobile-first layout, collaborative editing, framework migration,
zoom/pan, per-user language on the server, translating user-authored content.

## Module map (frontend after refactor)

```
web/static/
  index.html            containers + data-i18n markup
  style.css             logical-properties, RTL-safe
  app.js                bootstrap + composition only
  js/api.js             fetch helpers
  js/state.js           project/result/selection state + events (tiny pub/sub)
  js/i18n.js            t(), locale switch, dir handling
  js/history.js         undo/redo snapshot stack
  js/editor.js          plan canvas: tools, handles, snapping, popovers
  js/profile.js         side view render + ground/wall editing
  js/inspector.js       selection details, decision trail, corrections
  js/tabs.js            annotations/knowledge/review/bom/inventory tabs
  i18n/he.json, en.json
  fonts/NotoSansHebrew*.woff2
```

Interfaces: modules communicate only through `state.js` events (`selection-changed`,
`topology-changed`, `result-changed`, `locale-changed`) and exported functions;
no module reaches into another's DOM subtree.
